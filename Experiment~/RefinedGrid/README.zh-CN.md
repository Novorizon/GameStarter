# 对照方案：细化逻辑格与导航时间步

分支 `experiment/navigation-refined-grid`，基线 `f67e8e6`。这是独立的替代实验，未修改业务生产代码或 SDK，不作为最终修复交付。

## 实验目的

原 4m/72 人场景在基线实现中只准入 52 人。此实验检查其中有多少限制来自“1m 格、250mm 单位半径、整段双格独占”这一离散尺度，而非世界实际空间不足。

两组使用完全相同的原世界：边界、粗格障碍矩形、基地中心/半径、原出生点、单位半径、攻击距离、候场中心距离上限、请求数与请求顺序不变。基线读取的 `NavigationScenario` 没有改动；独立几何检查器始终使用原粗地图检验实际移动，不以细格自己的可通行判断作为证据。

| 项目 | 基线 | 细化 |
| --- | --- | --- |
| 搜索格边长 | 1000mm | 500mm |
| 导航 tick | 50ms | 25ms，每原 tick 两步 |
| 单位身体半径 | 250mm | 250mm |
| 出生请求节拍 | 每原 tick 最多尝试 | 仍仅原 tick 边界尝试 |
| 规划时间范围 | 4096 × 50ms | 8192 × 25ms |
| 每次计划展开预算 | 200000 | 200000 |

细格原点为 `(-250,-250)`，所以格心为 500mm 的整数倍，原出生点与基地中心仍精确落在格心上，不引入出生偏移或接驳传送。额外边界格全部关闭。细格的可通行掩码要求整个保守方形占地仍位于原可走粗格内；原粗图的连续圆盘扫掠会再次拒绝任何越障或越界。

单单位的实际最大速度按微步缩放。原各速度档在 1m 格上的整数过境耗时，与两条 0.5m 边对应的物理过境时间一致；原混速场景也执行相同检查。若增加新的任意速度数值，需要重新核对量化与时间协议，不能直接认为此关系对任意整数恒成立。

## 原样复现

在此 worktree 根目录运行：

```bash
dotnet run --project Experiment~/RefinedGrid/RefinedGrid.csproj -c Release
```

需要 .NET 8。程序引用此分支真实生产领域源码、原 `Scenarios.cs` 和独立 `GeometryChecks.cs`；不引入 Unity API 模型或第三方避障包。

程序覆盖 5 个原场景 × 4 个固定 seed × 2 个分辨率，共 40 次。每个导航微步都检查双方连续圆盘间距、原障碍矩形、基地膨胀圆、速度上限、攻击距离/视线和实际目标格到达；全请求到达后保持 200 个原 tick。随后先删除六个攻击者，隔离验证六名原候场者补位，再提交六个增援请求，要求原攻击人数和存活总人数恢复。

补位分阶段进行，**未证明大量新请求与死亡同时发生时的旧候场优先级或公平性**。基线会先给新出生者保留空攻击位；若测试同时投放增援，要求“六个位必须全由旧候场者占据”并不是当前 API 保证。此区别已反馈主任务。

## 结论与剩余失败

结果见 [results.json](results.json) 和 [source-sha256.json](source-sha256.json)。

- 原 4m/72 人场景：粗格 52/72，细格四 seed 均 72/72；细格 24 人攻击、48 人候场。没有扩大世界或候场距离。
- 原单出生口 5m/72、原 12m/300、原单格窄口/48：两组均全请求抵达；细格及粗格的死亡补位与增援验证通过。
- 原 19×19、4m、200 请求：粗格 52/200；细格虽有 272 个几何候选，仍只准入 177/200，23 个请求未进入。**此项记录为失败，整轮程序返回 1，不把拒绝改成通过。**

所以格细化能改善过粗离散带来的空间浪费，但不能解决永久保通路策略与站位分配的全部问题。它还增加可同时攻击的格数，改变围攻节奏；主任务若采用，需要另验业务数值与 Unity 表现。当前同半径实验未覆盖 490mm 大体型的细格方案、混合体型、实际 500mm 森林逻辑图、IL2CPP 或设备性能。

主任务的逆向撤离入场见证及空位传播方案可以在原粗格上解决 72 人问题，优先级更高。保留本分支是为了保存实际尝试过的另一类方案及其明确失败，不能把它当作通用无死锁保证。
