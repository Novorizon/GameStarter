## 具体修复

- 所有 `HasAttackLine` 合法 holding 格都可作为最终攻击目标，外前沿只是偏好。
- 满员后以完整 SIPP 事务安排多层临时让路、真实进场和返程；所有路径成功后才创建新单位。失败不推进时钟、不移动旧身体、不留下试建单位。
- 异质单位占错兼容候场格时，将现有单位移到其独占合法内格，腾回排队 profile 所需位置。原请求在实际准入前始终留队。
- 已在场候场者也可通过多层门进入真实空攻击位。这个恢复模式以当前所有身体的完整预约和合法终点为准，允许未来空目标通过下一次协同重排恢复访问；普通新准入保留原有未来 profile/Small 独占位置保护。
- 只按真正 `Attacking` 记录 profile 历史份额，恢复目标按当前活体需求限幅；活体归零清除历史，新 profile 争取首次至少一名攻击。只让攻击合法集合严格更大的 profile 永久退到合法 Gather，其他临时门返回原目标。这是稳定服务与死亡恢复策略，不是所有历史峰值同时成立的承诺，也不会封顶普通空位晋升。
- 多层让路可临时移动同 profile 的已占位者，但只在明确的既有攻击恢复/兼容交换模式启用。永久退让者必须满足严格集合包含关系；入口不计攻击目标，追加入口时清除关系缓存。
- 先试近处缓冲布局，真实 SIPP 出场/通过/返场失败时完整回滚，再试旧保守布局；两次共享 200000 搜索预算。临停可用空 holding 或通行格，但不能算最终到达。
- 失败按 profile、入口、速度及真实目标/交通修订缓存。预算失败保留 `SearchLimitExceeded` 并退避 64 tick；真实死亡或路线变化立即失效。回滚恢复语义修订、参与者 traffic 标记及历史份额。
- `GoalDistances` 仅作静态地形启发式，未来才被占据的目标不作为静态墙；安全区间和扫掠预约继续决定真实通行。单目标的静态访问判据若已否决，提前返回，避免无效等待穷举。
