# 全合法驻留点与异质单位入场候选

此分支保留实际 Forest 地图、身体、速度、入口及目标距离，修复攻击前沿筛选漏掉合法内格、满员后异质单位无法进入，以及让路过程中死亡造成的兼容位置分配错误。生产代码快照见 `source-candidate.json`；父级完整 Domain 基线来自 `750f091`，逐文件摘要见 `source-parent.json`。

## 具体问题与处理

- 攻击外前沿原来是硬限制。现在所有 `HasAttackLine` 合法 holding 格都可作为最终目标，外前沿只优先选择。
- 44 Big 已占满后，2 Small 的独占内格仍然物理可达，但需要多层 Big 让路。用完整预约事务安排临时通行格、Small 经过和 Big 逆序回场；全部路径成功后才创建新单位。失败不推进时钟、不移动身体、不留下试建单位。
- 中途 Big 死亡后，Small 可能先占 Big 的候场格，导致最后一个 Big 排队而 Small-only 内格空着。先把这个现有 Small 重分配到独占合法内格。若它自己挡住让路路径，也先将它撤出，再完成多层让路及进场。排队 Big 此时仍为排队请求，不能假报生成。
- 布局软路径、依赖展开、缓冲点 flood 与事务 SIPP 共享搜索预算。超限明确返回 `SearchLimitExceeded`，按原请求保留队列。
- 失败按 profile、入口、速度及真实目标/交通修订缓存。预算失败退避 64 tick；真实死亡或路线改变立即失效。回滚同时恢复语义修订和参与者 traffic 标记，避免不同速度失败互相冲掉缓存。
- `GoalDistances` 只计算静态地形启发式。未来才被占据的目标不能作为当前静态墙；实际通行时刻继续由原安全区间及扫掠预约决定。这修复了慢堵口移除后 24/48 仍等旧表的回归，独立对照在 416 tick 完成 48/48。

Oracle 独立计算每 tick 连续相对运动圆盘间距、障碍矩形扫掠、基地与边界、速度上限、真实终点及攻击射线。生成 API 前后检查既有身体不移动、时钟不变。报告记录源码、测试、二进制、地图摘要，检查运行前后源和测试不变。

`Results/` 保存上述四例和 70 次补回的完整报告。过程中死亡的独立正式矩阵和旧 72 个目标的 56 项挑战由独立验收分支提供，避免把重复运行计作新用例。

## 时序与边界

满员 44 Big 的极端晚到场景仍采用保守串行事务。speed165 在 tick4000 请求，第一个 Small tick4870 到内格，四 Big tick6940 回场；第二个 Small tick7806 到内格，所有 46 人 tick9880 实际到位。没有死亡残留预约，但远缓冲点和每人串行返程有明显优化空间。报告另有 200 tick 稳态观察，不把这段观察当作最后入场时刻。

这是已验证输入的实际可执行方案，不是任意地图多智能体重排的完备性证明；低于所需搜索预算的请求保留明确的预算失败与排队状态。
