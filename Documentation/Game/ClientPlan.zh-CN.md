# 启动、玩家页面与战斗模块

当前产品工作名为“翠林守卫”。PC 与手机横屏，首版单人；正式账号与结算需要接入服务器。没有正式后端时，界面明确展示本地档案，不伪造服务器货币和发奖结果。

## 模块与边界

| 模块 | 所在层 | 对外职责 |
| --- | --- | --- |
| StartupScreen / StartupArtwork | AOT Game.Startup | 初始化前即可显示启动界面；读取实际启动/下载进度，展示失败；缓存已验证资源中的背景，供下次启动使用 |
| GameEntry | AOT 入口 | 创建启动展示、初始化资源/热更 Manager、启动热更；退出时取消并释放 |
| GameHotUpdate | AOT 更新步骤 | 发行选择、资源准备、下载进度和代码读取；不包含玩家页面和任务 |
| ClientFlow | 热更业务协调 | 打开玩家页面、进入塔防、返回玩家页面；管理本次客户端 UI/资源所有权 |
| Journey / Missions | 热更纯业务 | 本地档案、战斗统计、长期目标、等级配置；正式服务数据经后端适配进入，不把本地进度当作服务器授奖凭据 |
| PlayerHubView | 热更表现 | 名称/头像/等级、战绩、任务进度和出征入口；只发业务命令 |
| TowerDefense | 热更业务与表现 | 既有纯 C# 战斗；塔卡选定后显示可建位置，点塔显示实际攻击范围，结束/返回通知业务协调 |

GameEntry 和 HotGame 只调用模块 API，不承担具体 UI 组件、任务计算或玩家存档。启动界面必须早于热更 DLL 加载，因此最小实现属于 AOT；玩家页面和战斗属于热更。启动图片可以使用上一版缓存，首次启动保留内置图和独立 TMP 字体。进度条使用已完成步骤和 YooAsset 实际下载字节，不通过计时伪造下载百分比。

## 首版玩家页面与任务

页面展示头像、昵称、本地档案标识、探索等级、最高波次、累计胜利、消灭敌人和旅程任务；主操作进入林间哨站，结束后可返回。任务例：第一次胜利、累计部署三座塔、累计选择三次强化。任务完成与战斗结算均需防止重复计数；本地模式的探索进度与正式服务器经济隔离。

正式联网后扩充现有 IGameBackend：登录/刷新、读取玩家快照、任务列表/领取、开局 ticket、结算查询和提交。货币、掉落、正式经验、每日重置、任务奖励、关卡解锁和购买以服务器为准；客户端只提交命令/战斗摘要。任务领取和战斗结算都用幂等键及版本号，断线后查询同一请求结果。

## 数据表分组

| 配置 | 合理粒度与内容 |
| --- | --- |
| ClientTheme | 每套 UI 主题一行：字体、面板、图标、头像、启动/玩家页背景；资源按 ui/fonts 分组 |
| PlayerLevel | 每等级一行：累计经验门槛、称号；不保存玩家当前状态 |
| Mission | 每任务一行：名称、描述、目标指标/数量、前置和奖励组；多目标升级为 Goal 列表，不为每个目标单开表 |
| RewardGroup（正式经济接入时） | 每组一个奖励列表；物品/数量/权重按类型定义，不把各种奖励塞进一列字符串 |
| Stage | 关卡入口、地图/波次组、开局参数、解锁条件；不混入每一波的刷怪记录 |
| MapLayout | 地图地址、边界、路线列表、建造区域/占地；路线点和建造点属于同一地图，可用嵌套 Bean 列表和同工作簿子表，避免永远拆成大量小表 |
| WaveGroup | 波次序列及各波刷怪组列表；敌人/路线/开始 tick/数量/间隔，避免平行数组 |
| Tower | 塔定义、等级数值列表、技能/攻击类型、占地、模型与图标；升级不再永远依赖线性公式 |
| Enemy | 数值、移动/攻击类型、体积、目标规则、模型和动画资源；精英用变体/修改器，不复制全表 |
| Card | 抽取池、稀有度、权重、叠层及效果列表；效果使用有类型的 Bean，展示文本与计算值分开 |

当前路线/建造点、波次/刷怪已经分表实现；发布重构时应连同适配、二进制与校验一起迁移，不能只删除表。新增任务、等级和主题先采用完整可用的小表；物品、奖励、技能和成长在有实际业务后添加。配置表、玩家存档、服务器快照和发布清单是四类不同数据，不混为一张通用表。

## 建造与点击

已确定编辑路线、固定建造位置。固定点便于关卡设计与塔的射程平衡，不要求把点位永久画成巨大特殊格。底图只画自然地面，进入建造模式后动态显示可建区域；占用、金币不足和选中分别有状态。视觉草块和道路铺装采用相近尺度，逻辑占地以配置为准；塔可占 2×2 草块，不能据地砖花纹推断可建性。

点选已有塔应退出建造模式，显示这座塔的实际攻击范围和升级数据；点 UI 不穿透到世界。手机交互不依赖悬停和右键。

## NPC、攻击与避障

当前普通敌人沿编辑路线攻击基地，不攻击路外塔。塔的目标选择、射程判定与命中由固定 tick 领域完成，Unity Collider 只用于交互；显示圈来自同一数值。后续具备移动攻击能力的 NPC 使用“索敌 → 接近到停止距离 → 攻击 → 追击/脱离”的状态机，停止距离包含自身/目标体积和安全余量，不能把到点距离当成射程。

固定路线阶段优先路线内纵向间距、队列约束和有限横向车道；配置路线走廊宽度和单位半径，偏移不得离开道路或绕到池塘。移动期望与避让修正分开，位置最终仍受路段约束。拥挤时允许明确的排队/绕行规则，不依靠 Rigidbody 推挤改变领域结果。

RVO/ORCA 是局部速度避让，不能替代路线规划、攻击状态机或不可堵死校验。只有引入自由移动、召唤物、护卫/近战混战或动态堵路后，再评估导航网格/网格图加 RVO。先记录峰值单位数、卡死率和耗时；正式服务器复演还需处理浮点误差和固定 tick。当前不新增 RVO 依赖。
