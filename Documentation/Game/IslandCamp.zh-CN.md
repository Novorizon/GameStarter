# 海岛营地大厅

启动入口仍为 `Assets/Scenes/Bootstrap.unity`。正常流程是启动更新 → 漂流抵达序章（首次）→ 海岛营地大厅 → 林间哨站塔防 → 返回营地。大厅是固定海岛场景与独立 HUD，替代原来的城堡背景玩家信息页；场景在运行时由 CampSceneView 创建，不要求进入第二个 Bootstrap 或手动运行另一个 Scene。

## 玩法与建设

玩家被风暴送到无人海岛，初始已有一顶帐篷。打开海岛手记，领取抵达补给，建设围栏；前往塔防取得材料和胜利记录，再逐步修建庭院、小屋。

| 营地等级 | 外观 | 建设费用 | 额外条件 |
| --- | --- | --- | --- |
| 1 临时帐篷 | 帐篷、行李箱、营火 | 初始拥有；木材 40、石料 15 | 首次抵达故事 |
| 2 围栏营地 | 木桩围栏和入口 | 木材 30、石料 10 | 抵达故事已完成或主动跳过 |
| 3 石砌庭院 | 铺装、水井和小花圃 | 木材 55、石料 25 | 至少 1 次塔防胜利 |
| 4 海岛家园 | 小屋与完整院落 | 木材 85、石料 45 | 至少 2 次塔防胜利 |

点击营地可查看下一步建设提示；左下方确认建设。任务按钮打开海岛手记，显示目标、进度、材料/探索经验与领取按钮。已领取和未完成任务不能再次领取。右下方是塔防入口，返回时刷新材料、战绩、任务和建筑外观；切换期间不重复显示抵达故事。

建设材料来自任务与已结束的塔防，不通过无限点击或客户端计时自动制造。胜负补给由当前 CampLevel 配置决定，放弃未结束战斗不计补给。所有这些是本地玩法，界面明确标识本地档案；正式服务器经济接入后需要使用服务器状态，不能上传客户端余额作为权威结果。

## 模块与所有权

| 模块 | 职责 |
| --- | --- |
| ClientFlow | 营地/塔防往返、资源租约与生命周期；观察序章任务，保存失败时保留当前战报并重试 |
| JourneyProgress | 本地玩家档案提交，战绩、旅程目标与营地补给在同一次保存中发布 |
| CampProgress | 建设条件/费用、营地任务、领取幂等、补给计算；不引用 Unity |
| PlayerHubView | 大厅 HUD、任务/建设命令和提示；不计算奖励或建设费用 |
| CampSceneView | 固定海岛底图与四级 3D 建筑表现、场景选择、相机和光照；停用时恢复其拥有的环境光状态 |
| CampMissionView | 营地手记窗口与任务状态展示 |
| CampArrivalView | SDK StoryPlayer 的 TMP 呈现器，显示资源中的三段抵达对白；核心推进、取消、跳过和结果使用 SDK |

GameEntry 的初始化顺序不增加营地业务；HotGame 仍装配通用系统后调用 ClientFlow。没有新增全局营地单例或第二套窗口框架。

## 数据、剧情与资源

当前共 14 张 Luban 表。营地只新增 CampLevel 与 CampTask 两张：前者保存完整等级费用/条件/补给，后者保存目标与奖励，不为每个建筑外观或每个任务目标再拆一张表。ClientTheme 增加海岛地图地址。

`Assets/GameAssets/Camp/Art/Island.png` 是 imagegen 生成的固定海岛底图，YooAsset 地址 `Camp/Art/Island`、标签 maps。`Camp/Story/Arrival` 是故事 JSON 资源，标签 story；段落、稳定故事 ID/version 随同一资源版本发布。公共面板、图标/头像与字体仍按 ui/fonts 管理。所有显示文字使用 TMP。

按用户授权，SDK 已更新到包含剧情的 `v0.1.0-preview.35` 固定提交 `5bf37118c412ce6f188340fe75661e54c0d91515`。当前使用纯核心 StoryPlayer 加项目 TMP 呈现器，未修改 SDK。Completed 或玩家主动 Skipped 才记录已抵达；取消/失败不记录。序章没有服务器奖励命令，抵达补给需要在手记中单独领取。首批内容为中文资源文本；完整多语言、配音和视频留到有相应内容后接入。

业务档案从 version 1 迁移到 version 2，旧昵称、战绩、等级经验和已完成旅程任务保留；旧版从未拥有营地字段，因此显式创建初始营地，不能把 Unity JsonUtility 为缺字段创建的空对象当作有效营地。营地自身使用 format=1 校验；不支持的格式保留原文件并报错。

建设、任务和战斗补给先计算新状态，完整档案保存成功后才替换当前状态。任务与当前战报防止重复领取；这不替代服务器事务或跨设备经济账本。保存失败后的待处理战报只由本次客户端生命周期保留，尚不提供程序崩溃后的结算恢复。

## 美术与后续内容

海岛底图、现有面板/头像/图标为生成资源；帐篷、围栏、庭院、水井与小屋当前仅为 Cube/简单几何体占位，用于检查位置、尺寸和建设状态，不继续精修 3D。用户通过 Meshy 提供正式模型、材质和 LOD，交付要求见[制作清单](MeshyBrief.zh-CN.md)；替换由表现层和资源映射处理。后续可增加玩家角色驻留、采集点、更多设施、角色任务和海岛章节，不把模拟经营系统一次塞进大厅入口。

卡牌基础显示已接通表中的 rarity/iconIndex，使用白/绿/蓝/紫/橙品级名称和颜色；抽取仍为原有单池权重。飞入、粒子等演出继续按[卡牌规划](CardDraft.zh-CN.md)后续制作。

验证报告与实际截图见[交付记录](../TowerDefense/Delivery.zh-CN.md)。云端 Editor 的画面/输入测试不代表真机性能、正式服务器结算或 IL2CPP 已通过。SDK 升级及热更程序集引用变化需要重建匹配的主包基线。
