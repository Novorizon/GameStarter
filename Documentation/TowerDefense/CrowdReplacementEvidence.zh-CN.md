# 塔防敌群移动与接战替换方案

## 已确认的问题

当前林间哨站沿预设中心线行军，到基地近区才用按体型缓存的距离场搜索站位。主路遇阻时，单位沿线走到仍有净空的位置再停下。十字路口的两队在无墙情况下都挤进了冲突区。第 1200 刻已有 14/44 只入场，基地仍未受击，两队队头都无法继续前进。这是道路交通故障。另一个限宽场景在逐步移除已命中者后有 34/34 只实际命中，但单独释放一个攻击位后，180 刻内没有单位补进去。清场通过和单次补位通过是两项验收。 [道路实现](../../Assets/HotUpdate/TowerDefense/Domain/FightSession.TerrainTraffic.cs) [逻辑场景与复现](../../Verification~/NavigationScenarios/README.md)

目标是让敌人沿玩家能预判的进攻方向移动。过弯时沿路转过去，窄桥上收成能通过的队形，十字路口在冲突点之前让行。到基地时先在来向接战，后续单位从仍有空间的一侧展开。打不到基地的单位在通道以外候补，空位出现后再接近。

| 问题层 | 子问题 |
| --- | --- |
| 路线与地形 | 保证通过规定的桥与弯道，区分可走地面和美术格线，按实际体型核对窄口净空，避免可走的窄道因网格起点改变而消失。 |
| 避障与交通 | 区分墙体、静止同伴和移动队列。检查弯道扫掠、不同速度的跟车、交叉口互锁、合流出口堵塞、路权公平性和放行后的继续前进。 |
| 围站与重排 | 区分攻击位已满、外围有可达空位、候补挡住了空位以及地形本身无路。多入口要同时保留小怪和重甲的进场连通，必要时先移动堵路候补。 |
| 攻击与补位 | 分开判定到位、射程、遮挡、前摇与实际扣血。既测无减员时能否正常展开，也测腾出一个位置后能否补上，再单独测逐步清场。 |
| 地图与表现 | 先用无美术的逻辑地图复现地形和流量问题，再与 Unity 画面的站位、道路与模型体积对照。 |

## 方案选择

| 做法 | 能解决的部分 | 本轮决定 |
| --- | --- | --- |
| 中心线继续加防碰规则 | 保住原出兵方向。单线跟车和暂停容易实现。 | 无法让已经互相封死的队头绕开或让出位置。作为现有基线对照。 |
| 作者走廊内共享流场、局部避让与冲突区准入 | 保留塔防布防预期。单位能在有限宽度内转弯、换侧、等待和重新跟路。独立处理交叉口容量。 | 在独立逻辑图上试验。净空接近单位直径的转角需要精确的几何连接点。 |
| 作者走廊内前视转弯、体型扫掠和冲突区准入 | 沿关卡规定的次序通过桥口，在能扫掠通过的地方圆顺转弯。可独立调整路口交通和基地接战。 | 接入当前游戏。保留从预设路线读取的必经顺序，转向与路权按实际净空和占用决定。 |

## GameStarter 的最小候选实现

### 从出生点走到基地或传送门

1. 保留路线顺序、入口与桥口。把折线作为作者定义的路线骨架，在它周围划出可行驶走廊。每个体型的可走单元取走廊、地图通行和真实半径净空的交集。运行时按当前路段和下一必经口选可读的方向场，防止 S 形路线相邻的两段互相串线。`roadHalfWidth` 是现有建塔排除参数。林间哨站该值为 415 毫米，整宽 830 毫米，小于重甲 920 毫米的直径。可行驶走廊须独立表达，桥栏、水面和岩石仍按实际碰撞判断。 [地图参数](../../Assets/GameAssets/TowerDefense/Maps/Map.json) [地形用途](../../Assets/HotUpdate/TowerDefense/Domain/BattleTerrain.cs)
2. 从当前路段目标向上游累计代价，缓存静态结果并生成每格下降方向。单位读方向场形成期望速度，能扫掠到前视点时圆顺切入下一段。用短时预测选择减速、停步或向可走一侧偏移。验证候选位移时，同时检查静态扫掠、单位相对运动和当前路段约束。保留上一刻让行侧，等障碍让开再回到首选方向，避免每刻换侧。
3. 计算两条路线按体型扩张后真正重叠的交叉、合流或窄口。等待线要在能挡住另一条路线之前。出口容得下一只完整的单位才准入，已进入者持有通行权，清出自身尾部或死亡后释放。等待按到达刻、路线与单位 ID 稳定排序。相邻重叠的冲突区合并，避免在前一区内等待后一区。它是本项目借鉴时空预约后的规则。宽路正常行进，不按路线编号强行轮流。

### 抵达基地后如何围攻

1. 按基地真实外沿产生候选，按兵种半径和射程检查站位。候选还要有连续可达路径、站立净空和合法攻击线。先找来向一侧能直接走到的位置，再试左右侧。相近位置优先保留较短路径且给后来者留出通路。已有攻击者留在有效位置。体型差异和障碍决定实际可同时攻击人数。
2. 按硬约束预留到达位置及即将使用的通道。规划时先验证站定后还能否抵达其他合法位置。如果某个落点会把仍可利用的另一块空间完全隔断，先安排能过去的单位，再填这个落点。沿移动路径释放已通过的区段。等待者站在道路和转向口以外，给必经口至少留出一只适用体型的扫掠宽度。没有安全候补点时，在入口前等。
3. 攻击位腾空时触发重新分配。若当前候补堵住去空位的唯一路径，先确认移开哪只单位即可连通，并验证它有可达的让行点。让行者走开后把接战机会给能到达的一只。已经站定的合法攻击者继续攻击。到位后由战斗逻辑检查距离、遮挡和前摇，命中时才扣血。传送门目标继续按到达出口结算。

### 受阻恢复的首轮参数

以下时间以当前 50 毫秒逻辑刻为单位，是待用同一组场景调优的起点。分别记录到下一路口或目标的进度。原地换朝向和微量来回移动都不能重置等待计时。正在等候明确占用的交叉口或前方实体满员时，继续等到占用变化。

| 持续状态 | 首轮处理 | 何时退出 |
| --- | --- | --- |
| 约 10 刻，0.5 秒，无有效进展 | 固定当前让行侧，比较前车是否在离开，避免左右交替试探。 | 净空恢复就继续。 |
| 约 20 刻，1 秒，无有效进展且前方未明确满员 | 在当前走廊或基地近区重算一次短路径，仍要求经过原有检查口。 | 成功后继续。失败则等待占用变化，避免每刻重算。 |
| 约 40 刻，2 秒，有可达目标但被静止候补挡住 | 同时验证候补的让行路径和目标重新连通，安排一只候补移动，再放行能实际到达的单位。 | 让行完成、目标被占用或地形改变后重新评估。 |
| 静态无路，或全是有效攻击者且没有余下站位 | 报告体型、通道或站位容量，在合法等待线停车。 | 地形或占用变化后再试。不能通过缩小体型、增加近战射程或瞬移来消除报告。 |

## 实际通过标准

- 在相同地图数据、种子、体型和出兵顺序下与旧版对照。记录入场数、通过关键路口的数量、最长等待、非法位移、体型扫掠重叠、攻击者与候补人数、实际命中和单空位补位耗时。固定种子重跑时对比每刻的关键状态。
- 真实林间哨站检查桥口、转弯和基地接战。通路开放时普通和重甲均通过预定入口。短停后应继续走，普通怪不按 ID 被强行交替分到两列。图中带回压的队伍和单独过路的单位都要观察。
- 无墙十字路口两路各能通行并命中，堵住出口时等待者停在冲突区外。完全封闭的桥或基地通道作为负对照。体型限宽的 820 毫米通道仅让 600 毫米宽的单位通过，960 毫米宽的单位走它合法的另一条路。 [场景定义](../../Verification~/NavigationScenarios/README.md)
- 基地饱和时单独测试一次释放不同方位的合法攻击位。静止候补可以让路且仍有连续可达路径时，应观察到让行、补位、前摇、实际扣血。记录单次结果，再另测连续清场。正在等待和绕行的敌人均不造成伤害。
- 用 Unity 实际画面看一段从出兵、通过弯道和路口到接战的连续过程，再核对逻辑图与底图是否一致。看到道路上明显可走的位置仍长期停滞时，先查真实体型、路口占用和有效站位诊断。

## 实现与对照

原型的斜交路口可以通过，但只把导航网格平移 73 毫米，0.98 米窄道中的两只重甲就停住了。两名候补需要依次让路的场景也失败。加入精确的窄口连接点和有限的候补重排后，11 个独立逻辑场景通过重复验证。 [原型验证](../../Verification~/CrowdFlowGenerality/README.md)

游戏接入采用前视转弯和扫掠检查，路线重叠处由独立的通行权调度放行。进入最后一段且地形、体型均可通行时，允许从多个位置转入接战区。攻击位置给必经道路留净空。多入口分配候补时，模拟单位站定后的实体占用，检查仍有当前或待出场单位的入口和体型能否抵达原来剩余的空位。攻城网格依据主入口统一朝向，以消除地图直角旋转造成的落位差异。

扩大范围、只优化最近入口的落位、为所有单位预留固定通道都做了无减员对照。固定通道降低了林间哨站的候补容量。给多入口保留剩余可达空间后，三入口场景的 62 只单位全部到达攻击位或候补位。一个方向的出兵推迟 30 秒时，末队在约 208 秒全部到位，期间没有移除单位。林间哨站的旧拥堵快照用短距离让位放进了一只，原有队形中剩余的连锁阻挡仍需更多实体腾挪。新的入场规则从开局验收。 [可复跑场景](../../Verification~/NavigationScenarios/README.md)
