# 界面、美术与地图表现

## 导航与界面职责

正式流程建议为“启动更新 → 登录 → 大厅 → 关卡/难度 → 战前确认 → 战斗 → 结算 → 大厅”。当前已实现“启动更新 → 首次漂流序章 → 海岛营地大厅 → 出征 → 战斗 → 返回营地”，大厅有四阶段建设、任务手记和本地玩家摘要；账号登录、关卡选择和服务器领奖接入后再扩充对应页面。营地与战斗的 3D 使用简单几何体占位，正式模型由用户通过 Meshy 提供。

| 界面 | 内容与操作 | 正式 UI 框架对应 |
| --- | --- | --- |
| 启动更新 | 本地已有界面资源、版本和下载进度、失败重试 | AOT 固定控制逻辑；界面图像/布局资源可更新，下次启动使用 |
| 登录 | 渠道/游客入口、隐私信息、连接状态、错误重试 | Page + 阻塞 Overlay；实际账号方案需确定 |
| 大厅 | 玩家摘要、开始游戏、关卡入口、设置 | Page；不展示客户端自造的正式货币余额 |
| 关卡与战前 | 地图、敌人预览、难度、可用塔、预计奖励、开始 | Page / 可选确认 Popup；实际开局 ticket 返回前禁用重复提交 |
| 战斗 HUD | 基地耐久或逃脱数、局内金币、剩余敌军、击杀积分和增援时间 | 数值来自领域快照 |
| 造塔/升级 | 可建点、塔型、价格、预览范围、升级费用及收益 | 底部 Panel；钱不足显示具体原因，不仅改变颜色 |
| 三选一卡 | 全屏遮罩、三个卡牌、效果和叠层信息 | 模态 Popup；领域暂停，选择成功后关闭 |
| 暂停 | 继续、设置、放弃确认 | Popup；手机返回键优先处理当前顶层窗口 |
| 结算 | 成败、波次、构筑摘要、奖励预览/待确认状态、重开/返回 | Page/Popup；正式奖励以服务器结算响应为准 |
| 断线状态 | 重连中、结算待联网、重试或重新登录 | Overlay / 非阻塞状态条；不吞掉正在进行的合法选卡 |

当前 `TowerDefensePrototypeView` 使用业务模块拥有的 Canvas。状态在左上，系统操作在右上，塔卡在右侧滚动列表中，选中塔后才显示底部详情。它会共享项目已有 EventSystem，必要时创建自有输入系统。Dispose 清理自有对象和相机。正式 Prefab 制作后，可把窗口迁到现有 `UIManager.Pages/Popups/Panels`，保留 Presenter 与领域命令接口。

现有 UI 框架的 `OpenToken/Track` 用于一次窗口打开期间的任务与订阅，`DestroyToken/TrackUntilDestroyed` 用于整个视图实例。页面关闭要退订、取消迟到请求；Prefab 的 YooAsset 租约由现有 `YooAssetUIAssetLoader` 随原生实例销毁归还。业务不直接调用共享 `ReleaseHandle(location)` 来销毁其他窗口仍使用的资源。

## 战斗布局

横屏战场保持中心清晰，路线、怪物和可建点不能被常驻 HUD 遮住。推荐 1920×1080 作为布局参考而不是固定屏幕尺寸：

| 区域 | 规划 | 触控与可读性 |
| --- | --- | --- |
| 左上 | 剩余敌军、基地耐久或逃脱数、金币和战斗状态 | 四组状态各有图标和独立数值，目标附进度条 |
| 右上 | 暂停、营地和系统菜单 | 系统操作集中在同一处 |
| 地图中心 | 路线、基地和建造预览 | 选卡后显示半透明塔模型。可建时保留原色，无效落点染红 |
| 右侧 | 可滚动塔卡、特长、价格和本波情报 | 选中卡有独立边框，金币不足的卡仍显示价格 |
| 底部 | 塔名、等级、攻击力、攻速、射程、升级与出售 | 三项属性纵排，对照当前和下一级实战数值。金币不足在升级按钮下方提示 |
| 塔旁 | 塔名、等级、升级与出售 | 右键点塔打开快捷菜单，靠边时自动换侧或贴齐战场边界 |
| 部署面板底部 | 击杀积分、增援倒计时和开场控件 | 备战时可立即开战，之后自动增援 |
| 三选一 | 居中三卡，标题、当前叠层和效果文字 | 每张整卡可点击；不依赖悬停提示；手机上文字不可压成一行小字 |
| 结果层 | 成败、构筑摘要、操作按钮 | 表示结算 Pending/Confirmed，避免误导已经领取奖励 |

PC 的数字键、快捷键和悬停详情作为附加方式。先选塔卡，再移动鼠标查看放置预览。模型保持原色时可以左键放置，右键或 Esc 取消本次放置。触屏可按住拖动预览，松手时放置。预览和提交共用同一套落点、资源和占用判定。点击 UI 会阻止穿透到地图。返回键遵循现有 UI 顶层优先级，选卡不能因按返回而跳过规则。

布局通过 CanvasScaler 与 safeArea 适配 16:9、19.5:9、20:9 和常见平板比例。正式验收还要检查系统字体缩放、中文长文案、色盲可辨识和左右手遮挡。原型中的像素尺寸不是已验证的毫米触控规格，至少在目标手机上实测后定版。

## 轻卡通视觉方案

采用低多边形台地场景：块状草皮、厚土层、岩石松树、砂岩路、池塘和木桥。松绿色面板搭配铜金边框、暖白 TMP 文字和蓝色建筑旗帜；塔卡、属性与强化使用同一套低模图标。全部文字使用 `TextMeshProUGUI` 和明确加载的 `TMP_FontAsset`，不混用 Legacy Text/默认内置字体。稀有度同时使用边框样式和文字/符号，不能只靠红绿区分。地图中心保留清晰路线和空建造区，伤害、增益和漏怪的表现避免遮挡路线。

imagegen 制作地图、卡牌图标、面板/卡框和按钮底图。图像不烘焙可变中文、价格、血量和效果数值，这些由 TMP 文本渲染。需要单独使用的 UI 元素生成透明背景、留出一致边距，分别导入为 Sprite；不要把整张设计稿直接当作可交互 UI，也不要依赖一张未切片大图上的假按钮。

| 素材 | 建议源文件 | 运行时要求 |
| --- | --- | --- |
| 地图底图 | 无 UI 的横屏俯视/斜俯视地图，标注可行走通道和空闲建造区 | 2D 图像与逻辑路线/建造点对齐；不能从图像自动推断可通行区域 |
| 卡牌图标 | 攻击、攻速、射程、金币、修复等独立图标 | 清晰轮廓，透明背景，统一光向；效果/稀有度由 UI 组合 |
| 卡框/面板 | 中性底板，边缘可延展，内部留白 | 适配九宫格的边框保持独立；正式 UI 设置 border、切片及拉伸测试 |
| 按钮底图 | 主要、次要、禁用、选中等状态 | 文字独立；不能仅用亮度表示禁用或不足金币 |
| 3D 单位 | 当前为程序化平面法线石塔、蓝顶基地和矮身怪物；网格共享 | 当前没有正式骨骼动画和 LOD；图片生成不等于完成3D资产 |

资产清单 [ArtSources.json](ArtSources.json) 记录 imagegen 生成提示摘要、日期、用途、导入设置及文件哈希。图标为 3×3 图集，卡框/面板使用 180px 九宫格边距；文字和价格全部独立渲染。运行时所有地图、图标、卡框和字体均通过 YooAsset 租约取得，由业务 owner 在 UI/场景对象销毁后归还；不依靠 Inspector 直接引用把热更资源偷偷打回场景内置依赖。

战斗 HUD 单独使用 `Common/UI/BattleHud`。`Tools~/build-battle-hud.py` 生成带柔光的九宫格面板、卡框、按钮与标签，以及 16 个功能图标。选中的塔卡和塔头像使用高亮边框。耐久条的轨道、常态填充和低耐久填充使用独立的胶囊图形，端帽按条高等比缩放。塔的立绘和金币图标取 `Common/UI/Icons`，名称、等级、价格和状态由 TMP 渲染。

## 字体与资源分类

战斗 HUD 采用 Noto Sans SC 的 Medium 500 和 Bold 700 字重。`Tools~/build-battle-hud-font.py` 从 OFL 许可的变量 TTF 生成项目命名的静态子集，Unity 菜单 `Prepare Battle HUD Fonts` 生成 TMP 资产。`BattleHudMedium` 关联 Bold 字形并回退到 `GameUI`，覆盖关卡配置新增的文字。发行包携带 `ThirdPartyLicenses/Battle-HUD-Sans.txt`。

TMP 字体使用合法来源的 Noto OTF 子集，随工程保留 OFL 授权与来源记录；字体更名、子集和分发仍遵守授权要求。源 OTF 必须作为动态字体的运行时依赖一起保留，不能只上传生成的空 SDF 资产。子集至少覆盖当前中文文案、数字、拉丁字符和符号；未包含的字需要扩充子集或配置经过验证的回退字体，动态字体不能生成源文件里不存在的字形。

`GameUI` 使用动态 SDF、1024×1024 图集并开启多图集，按实际出现的中文补字；避免一次生成巨大静态中文字库。上线前记录目标手机的图集页数、材质数量、源字体内存和峰值文本开销。多图集会随字形增多占用更多内存，不是固定 1024 大小就永远只有一张纹理；运行过程中不要每次开窗新建一份字体资产。

| 分类 | 当前内容 | 地址/采集原则 |
| --- | --- | --- |
| maps | imagegen 地图底图 | 地址如 `TowerDefense/Art/Map`；与关卡几何数据一起版本化 |
| ui | 卡牌图标图集、透明卡框及以后按钮/面板图像 | 地址如 `Common/UI/Icons`、`Common/UI/Panel`；图集绑定不要因整理磁盘目录而悄悄改地址 |
| fonts | `TMP_FontAsset`、源 OTF、材质和图集依赖 | 字体入口 `Common/Fonts/GameUI`；源字体由依赖关系随包构建，授权文件保留在源码中 |
| models / vfx / audio | 当前单位由代码生成共享网格；正式模型/动画/音效待制作 | 有实际资源文件和使用方式后再配置采集，不创建空采集目录或虚构资源地址 |

分类首先用于明确生命周期、查找和后续分包，不代表每个小目录都必须单独一个 YooAsset Package。当前统一 DefaultPackage 可以按 groups/tags 组织 maps、ui、fonts，初期保持同一资源版本和统一下载；后续下载预算确实需要时再按标签分批。`ClientTheme` 保存公共 UI 地址，`TdStage` 保存地图地址，业务代码不拼磁盘目录。

## 2D 地图与 3D 单位

使用固定 55° 正交相机。逻辑二维坐标映射到 Unity XZ 平面，Y 表示单位表现高度。地图图片已包含台地与透视表现，因此 Sprite 面向相机放在所有 3D 单位之后，避免把预渲染透视再投影一次；台阶和地形厚度是图像表现，当前不运行 3D 地形寻路。

当前完整图像为 1672×941，对应逻辑宽 22000、深 15120。像素锚点转换为 `x=(pixelX/1672-0.5)*22000`、`y=(0.5-pixelY/941)*15120`。`tdroutepoint.xlsx` 保存 18 个路线点。`tdbuildslot.xlsx` 保存 350 毫米吸附网格上能容纳半径 420 毫米底座的候选点，共 407 个。地面由人工标注，道路、水岸、台阶、基地及障碍物的占地要逐处核对。旗帜这类悬空装饰按落地处划定占地。虚影脚下的圆圈显示实际底座占地，并与模型一起标记当前落点的有效性。已建塔会排除底座重叠的候选点。替换地图后需重新划定地面、校准表坐标并生成 Luban 数据。

地图数据至少保存逻辑边界、路线点、建造点、基地锚点、出生点和地图表现 ID。选中塔卡后，放置预览在命中候选塔位时吸附到塔位中心，未命中时跟随指针并显示红色。退出建造后，点塔可查看实际射程与底部属性面板。改变几何关系时同步发布对应关卡数据。

怪物不依赖 3D NavMesh：领域沿编辑折线累计距离移动，表现插值到对应坐标并朝移动方向转向。塔只放在固定点，射程和目标选择由领域完成。路线编辑应检查相邻点重叠、越界、未连到基地、路径穿过建造占地和过短路径。后续支持多入口/多路线时，由刷怪组引用 RouteId，路线可在关卡编辑工具中可视化；不需要因此引入运行时寻路。

若未来改为自由堵路，需要新增网格/导航图、建筑占地与动态障碍、建造合法性、路线重算、不可堵死校验、怪物重路由与服务器可重放规则。这是玩法变更，不是把当前折线移动替换成一个 NavMeshAgent 就完成。

## 性能与验收

先在目标手机设定预算，再决定敌人数、特效密度、贴图尺寸和是否使用 GPU Animator。原型允许简单对象便于查看；正式版本需测峰值怪物数、每 tick 目标查询、Canvas 重建、文字更新频率、生成/销毁和资源内存。对象池、空间索引和 ECS 应根据 Profiler 热点引入，不为少量演示单位先套完整 ECS。

至少验收：三选一时模拟冻结、按钮无穿透、快速连点不重复扣费、切后台不爆补 tick、分辨率变化不遮挡地图、重开不叠加相机/EventSystem/事件监听、断线不把待结算奖励当已到账、所有 UI 资源在关闭和退出后按租约释放。批处理编译不能替代触控、实际画面、声音和目标手机性能验收。
