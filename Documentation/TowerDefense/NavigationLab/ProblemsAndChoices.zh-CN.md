# 本轮问题拆解与方案边界

目标是在原地图、原身体尺寸和原请求数量下，让敌人实际走到基地周围的合法位置，持续攻击或稳定候场；无炮塔测试不能通过杀死、隐藏、传送敌人结束拥堵。A–E 的输入和判据相同，商业项目的名称只说明资料来源。

## 要共同解决的问题

| 层次 | 子问题 | 验证方式 |
| --- | --- | --- |
| 世界几何 | 通行区、边界、基地占地、不同半径的净空；格心可走是否意味着整段可走 | 原始地图指纹；圆盘对矩形、圆和边界的连续扫掠 |
| 全局路线 | U形与死胡同、窄口、多入口、大地图；地图变化后的缓存失效 | 保留原输入；核对实际行走，不能只检查返回的路径节点 |
| 同伴避障 | 追赶、迎面、交叉、汇流、停止者与移动者；同帧停止之后的连锁冲突 | 每5ms检查相对运动的最小间距、速度与身份 |
| 围攻目标 | 可达攻击位置、候场位置、目标所有权、近侧拥堵而远侧有空位 | 实际位置/射程/视线、合法最终Goal、队列与死亡守恒 |
| 交通协调 | 攻击者挡住入口、不同体型争用位置、内外射程互相封锁、晚到者饥饿 | 原72反例、实际Forest44/45、44稳定后晚到2人、射程公平性 |
| 动态生命周期 | 移动中死亡、驻留者死亡、无新出生时旧候场者补位、堵路后开放、目标变更 | 事件必须真实触发；检查释放和补位；接口本身不能移动身体 |
| 拥堵恢复 | 区分无解、容量排队、暂时等待、规划预算失败和有解却停滞 | 独立可行依据、实际轨迹与长期进展；安全停步不等于到达 |
| 运行与资源 | 多实例隔离、暂停、重放、分配与搜索峰值、Unity运行差异 | 新实例重放、交错实例；记录所有API成本；另做Unity/Mono验收 |
| 内容制作 | 逻辑净空、入口与围攻环是否适合原身体；2D底图与坐标投影是否吻合 | 先保留原反例诊断；若改地图，单独记录地图版本与变化理由 |

路径搜索、局部避障和围攻位置调度是不同职责。局部速度解算器不会自动为远侧空攻击位安排进场次序；流场也不会自动决定谁让出最终位置。因此，各候选都必须说明自身的塔防适配，不能把额外调度包装成商业原算法。

```mermaid
flowchart LR
    W[地图、身体与目标规则] --> G[合法目标与所有权]
    G --> P[全局路径或流场]
    P --> S[局部转向、避让与让路]
    S --> M[实际连续运动]
    M --> O[独立几何、身份与到位检查]
    O --> R[进展诊断与动态重规划]
    R --> G
    R --> P
```

C和D使用了不同的实际架构，没有把同一个BFS换名称。E没有复制AGPL重实现源码。所有未披露的参数、Goal分配、物理执行与解堵均属于本项目代码，其失败不能直接外推成商业游戏原实现失败。

## 为什么保留多个变体

B0回答用户指定组合本身的表现；B1检验增加协商是否有收益。C、D、E的开发变体用于验证具体假设，失败或中止都保留身份、源码和报告；最终统一矩阵选定一个整体版本，不按场景拼接不同版本的最好结果。

需要先修正明确的实现缺陷，再讨论架构限制。例如，浮点执行门错误、路点回追、缓存失效和真实LOS漏路属于实现问题。修改一个阈值可能缓解症状，也可能破坏另一场景，必须回到同一组完整输入检验。

## 怎样理解“普适性”

统一stress矩阵包含49个明确场景；完整full矩阵的41项是其中逐字相同的子集，不重复计为额外覆盖。还包括200个完整逻辑tick的驻留观察、新实例重放和多实例隔离。失败保留原人数、身体、目标与时限，不改成更宽地图或更少单位后覆盖原报告。

这些证据可以说明当前版本在哪些条件可靠、在哪些条件失效，不能证明任意地图或任意人数完备。当前模型是2D地面圆盘、二值地形、固定速度上限和离散最终Goal；加权地形、多高度、水陆/飞行、加速度、持续移动基地扫掠、真实手机与IL2CPP尚需另验。

若最终仍有无法消除的结构性阻塞，再评估通道净宽、围攻环和候场区域，必要时先生成通过验收的逻辑地图再绘制底图。地图调整是内容方案，必须保留旧反例，不能据此声称获得通用解法。
