# 林地关卡的逻辑地图

运行时地图为 [ForestNavigation.bytes](../../../Assets/GameAssets/TowerDefense/Data/ForestNavigation.bytes)，由 `NavigationLayout.Parse` 读取。YooAsset 地址是 `TowerDefense/Data/ForestNavigation`，资源采集组是 `TowerDefenseNavigation`，标签为 `navigation`。原有 `Map.png` 没有改动。

这是一份人工编写、可以审查的玩法地图。道路肩部、水池轮廓、台地和装饰占地按现有底图与业务坐标近似采样，不能理解为从图片准确识别出的物理碰撞。逻辑地图负责限定游戏规则；覆盖图用于找出美术与规则不一致的地方。

## 坐标与格式

全部距离使用毫米。网格为 44 × 30，每格 500；左下角边界为 `(-11000, -7560)`。文本行按北到南保存，运行时数组索引为 `y * width + x`，Y 从南向北递增。格心相对于原点偏移半格。

底图覆盖 22000 × 15120，网格覆盖 22000 × 15000；未纳入的最北侧 120 毫米是不可进入的装饰边缘。基地中心为 `(7553, -3527)`，独立的圆形占地半径为 1100。此半径保守覆盖目前约 1700 × 1400 的基地基础，换模型时需要重新核对，不能仅调整显示比例。

文本先包含固定版本与五行元数据，再包含声明数量的地形行：

```text
NAVGRID 1
size 44 30
cell 500
origin -11000 -7560
target 7553 -3527 1100
rows north-to-south
```

以 `;` 开始的整行是注释。解析器支持 UTF-8 BOM、CRLF 和空行；拒绝未知版本、元数据缺项、行宽/行数不符、未知符号以及缺少出生点、基地地面或驻留区域。

| 符号 | 规则 |
| --- | --- |
| `.` | 道路与肩部，可通过，不能作为最终驻留位置 |
| `+` | 基地外圈/入口预留通道，可通过，不能作为最终驻留位置 |
| `a` | 可供分配攻击或候场目标的区域，仍需体型、距离、视线和进场连通性检查 |
| `B` | 基地自己的地面；供视线检测，实体身体由独立目标圆盘禁止进入，不能驻留 |
| `S` | 出生入口，可通过，不能作为最终驻留位置 |
| `#` | 未开放的草地、地图边界或玩法隔离带 |
| `~` | 水面，不可进入 |
| `^` | 没有可用入口的高台，不可进入 |
| `*` | 树木、岩石等装饰障碍，不可进入 |
| `T` | 固定建造点预留占地，不可进入 |

`B` 的可走标记只让视线终点落在地面上，不能据此忽略目标圆盘碰撞。实际单位的格心与移动整段均需避开“目标半径 + 单位半径”。

## 本关空间选择

道路按既有 18 个编辑点连线，加约 650 毫米的中心线包络；保留蛇形路、桥与左侧回环。7 个固定建造点预留静态占地，即使未建塔也不让敌人穿过；这避免本关固定建造行为改变通路，但不能替代以后自由造塔所需的动态阻塞验证。

基地周围开放原先只作为背景的草地作为接近、环绕与候场区域：大致 X 为 2500–10000、Y 为 -6000–-1250。北侧保留封闭隔离带，使怪物不能从上方中段道路提前转入基地而跳过回环。外侧预留通道与入口接近通道使用 `+`（参考方案按两格预留，受地面边界和装饰影响，局部已收窄），不分配永久站位；其他可用格使用 `a`。

此处存在明确的内容约定：道路肩部可能比画面上的沙土边缘宽；基地周围的部分草地现在允许移动，而更外侧相似草地仍由 `#` 封闭。水池、高台和装饰按格近似，不是逐像素碰撞。右侧/西南装饰周边的局部缺口不能笼统描述成处处双格宽；独立通道和整组站位是否持续可达，要以实际群体测试为准。

初次覆盖审查发现南侧通行预留延伸到了画面土壁，已把南沿从 -6500 收回到 -6000；删除的是通行格，东沿也从 10500 收回到 10000，以使单位身体不越出右侧地面；半径250的44个驻留候选未变。这个修正依据地面边界。最终群体与 Unity 结果见[本分支验收报告](Verification.zh-CN.md)，静态连通审计不能代替该结果。

后续重绘底图应参照逻辑覆盖图，明确道路边沿、可走草地、树根和岩石占地。若需要扩大候场区或调整隔离带，应同步修改资源并重跑群体测试；不能只放开所有草地来掩盖调度缺陷。

## 可重复审计

在仓库根目录执行：

```bash
python3 Tools~/audit-forest-navigation.py
```

工具需要 `openpyxl` 和 `matplotlib`。默认读取当前 ASCII 地图，检查版本、尺寸、符号、出生点、7 个塔位和前 17 个旧路线点，验证半径 250 的单位从出生点经过合法四邻边到达全部驻留候选。最后一个旧路线点是基地中心，必须位于身体禁止进入区，因此不作为移动终点验证。

结果输出为 [覆盖图](forest-navigation-overlay.png) 和 [地图审计 JSON](forest-navigation-map-audit.json)。覆盖图在不改变原图的情况下标出逻辑区域、旧路线、塔位与基地圆盘。

当前静态结果是 346 个地面格，其中 322 个格可由半径 250 的单位抵达，44 个格可作为驻留候选。**44是半径250的静态候选数**；相同地面上半径200可驻留45个、小体型与大体型混合可达46个。候选统计不能自行证明同时可达：最终另通过44/45饱和、44大体型先稳后2小体型晚到，以及死亡补员的完整行走验证，见[动态验收](Verification.zh-CN.md)。出生点到最近候选的合法最短路约 47000 毫米；原 18 点折线全长约 50497 毫米（含进入基地的末段），用于辅助检查没有连接上方道路形成大幅捷径。JSON 同时记录 ASCII 与原图的 SHA-256，使审计结果能对应到具体输入。

正常关卡的最大一波为 30；单波围攻、126 只合并波次以及更大人工地图的压力结果分别见[最终验收](Verification.zh-CN.md)。

`--write-layout` 会使用工具中保留的参考几何规则重建并覆盖 ASCII 地图，供有意调整地图时使用；它不是 Unity 导入步骤，也不应在已有手工修改时自动调用。
