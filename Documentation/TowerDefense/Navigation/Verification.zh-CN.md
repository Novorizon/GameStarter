## 实验暴露的问题与修正

| 观测 | 最终处理与验证 |
| --- | --- |
| 只检查格心无法发现转弯中的身体接触、偏心基地穿弦 | 移动整段保守预约源/目标格，检查膨胀基地圆；独立连续扫掠验证 |
| 窄口未来预约冲突被当成永久无路 | 分出临时预约阻塞，外部排队重试；48 个单位真实到位 |
| 长射程先围成外环，短射程无法进入空内环 | 开始前注册全部身体/射程与入口；跨类型保进出通路，内外环死亡补位通过 |
| 最近目标贪心导致原 5m 场景只接纳 69/72、原 12m 场景只接纳 271/300 | 引入公共通路骨架指导端点排序；保持原地图/半径后，两种 72 人及 300 人场景在四个 seed 全部抵达 |
| 真实 126 请求的稳定容量等待，200 tick 仍新增 521,800 次展开 | 按站位修订缓存永久准入失败；现为 0，死亡后正确失效并继续生成 |
| 统计未知射程的格数竟改变路径 | 几何缓存与已注册目录分离；800 tick 完整轨迹、搜索计数和目标在有无查询时一致 |

保留原 4m 场景：72 个请求中四个 seed 均准入 52、拒绝 20；所有准入者真实到位。小图 200 请求场景准入 52、拒绝 148。它们验证当前承诺下的安全拒绝，不证明地图物理无解，也不隐藏优先规划的局限。另有永久禁止驻留通路的停车证书场景，纯射程外停车容量分别为 92、84、332；与自由候场场景分别测试，不用换地图后的结果冒充原场景通过。

## 耗时与剩余边界

独立 Unity 复跑的正常 30 人波，最大单次 `FightSession.Step` 调用为 7.18ms，快速 30 人组为 10.68ms；首组含首次执行开销，峰值 36.47ms。另一次[并行压力测试期间的原始报告](unity-navigation-parallel.json)记录到 130.81ms 的峰值，两份都保留。这里是调用的墙钟耗时，包含运行时和调度影响；差异未经逐项归因，不能转述为算法的纯 CPU 时间或手机帧率保证。原始报告同时保留验证与表现同步耗时。

最终压力整轮约 111.1 秒，含独立几何检查、逐组命令重放、记录与契约测试。300 单位人工地图的完整模拟耗时不能当作单帧寻路预算；真实手机、硬件 GPU、IL2CPP、转向耗时、变速/击退、动态堵路及移动目标均未验收。

当前版本解决本关静态地图与固定运动规则下的寻路、身体避障和围攻；仍是有预算的优先规划。公共骨架用于目标排序，回退仍可使用骨架格，安全由原预约和通路检查维持，不能继承 TP/COBRA 的通用完备性保证。增加新地图或玩法时继续使用同样的失败分类、队列守恒和连续碰撞检查。

## 本地运行

使用项目固定版本的 Unity 打开 `Assets/Scenes/Bootstrap.unity`，完成启动后从营地进入出征。正式流程通过 YooAsset 加载 `TowerDefense/Data/ForestNavigation`，然后将几何注入战斗配置；GameEntry 不参与具体寻路。

战斗中按 F3 显示逻辑格、实际身体圆、预留目标、前进/候场/攻击人数和待生成数量。有未生成敌人且发生准入失败时，调试面板显示原因。出生排队中的敌人尚未进入模拟，不会叠在出生点，也不会从应生成数中丢失。

## 自动化检查

在仓库根目录运行：

```bash
python3 Tools~/audit-forest-navigation.py
python3 Tools~/verify.py --dotnet /path/to/dotnet
dotnet run --project Verification~/TowerDefenseNavigation/TowerDefenseNavigation.csproj -c Release -- --stress --output Artifacts/NavigationStress
```

地图审计需要 `openpyxl` 和 `matplotlib`。`verify.py` 需要 .NET 8，并按项目锁定版本获取 SDK 验证源码；也可以用 `--framework /path/to/com.novorizon.framework` 指向同版本的只读源码。它包含真实 Luban/导航资源接入、实际战斗策略与生命周期回归，以及导航的默认样本。`--stress` 对完整场景使用多个固定 seed，并逐组重放相同命令检查 Step 批次一致性。

独立导航测试直接编译生产领域源码。连续圆盘、障碍和基地圆的检查器单独计算几何最短距离，不用生产寻路函数的返回值代替碰撞证据。测试记录生成命令、轨迹、失败分类、真实抵达、预约数、搜索展开与耗时。显式停车位/通路证书场景与原始自由候场压力场景分开报告。

将一组轨迹转换为可离线拖动时间轴、点击单位查看目标与路径的 HTML：

```bash
python3 Verification~/TowerDefenseNavigation/visualize.py \
  Artifacts/NavigationStress/three-hundred-units-original-12m-1.json \
  Artifacts/NavigationStress/replay.html
```

真实 Unity 无塔验收：

```bash
Unity -batchmode -force-glcore -projectPath /path/to/GameStarter \
  -executeMethod Game.Editor.TowerDefenseNavigationValidation.Run \
  -logFile /path/to/navigation.log
```

此入口需要可用图形设备，不加 `-quit` 或 `-nographics`；由验收脚本在完成 Play、截图和退出检查后关闭 Unity。六个真实波次各自隔离运行，再运行最大波次的快速生成组。每组使用高生命基地、禁止建塔，保留全部敌人，要求实际到达目标格后继续围攻 200 tick。截图中的波次 `1 / 1` 来自这种单波隔离，并非将正式关卡改为一波。

输出在 `Artifacts/TowerDefense/Navigation/`：`validation.json`、逐组 CSV、正常画面和 F3 画面。JSON 记录 Unity/图形后端、地图 SHA-256、抵达 tick、攻击/候场人数、连续碰撞检查、基地伤害、分项调用耗时与退出状态。表现同步时间不包含延后执行的渲染和 GPU 时间。

完整营地与战斗流程另用 `Game.Editor.TowerDefenseValidation.Run`；Player 脚本编译用 `Tools~/unity-validate.sh compile`。无塔验收通过不能替代实际塔防的胜利、失败、选卡、暂停、重开和返回营地回归。

## 结果的解释

- 抵达必须是单位身体实际位于合法目标格，不能只看路径返回成功或分配了槽位。
- 候场单位不能扣基地生命；攻击者须满足距离、视线和攻击间隔。
- 普通波次必须全部生成并抵达。超容量压力用例另报告已接纳、队列和明确拒绝，不将其混作普通波次成功。
- `CapacityExceeded` 指当前已提交站位和保通路策略下无法安全接纳，不证明任意联合重排都无解。
- 无变化的容量等待应停止重复搜索；死亡或站位释放后必须重新允许准入和补位。
- 云端 CPU 计时用于发现回归，不作为手机帧率、硬件 GPU、IL2CPP 或原生 Player 的通过证明。
- 当前为固定地图、固定基地、固定体型/速度的四邻格运动。击退、变速、自由堵路或移动目标需要扩展预约协议，再重跑对应验收。

运行日志和完整轨迹在 `Artifacts/` 中，不加入源码。最终版本的可携带结果及代表截图应与对应源码、地图指纹一起保存，避免将早期通过记录用于后续修改。
