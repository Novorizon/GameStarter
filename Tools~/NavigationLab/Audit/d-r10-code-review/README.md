# D R10 八邻 HPA / FMM 只读代码审阅

对象为 commit `c1c129e`，开发版候选 DLL SHA-256 `305d2b753ec92c7377004906b4c1675273bccf203ae71ca1445d660f5e209552`。代码与实际查询 DLL 均有副本并由 manifest 绑定。这里是小型几何与路线查询，不是完整基准、新实例全场回放、Unity 或设备验收；未改候选、公共 harness 或原工程。

本次未发现新的确定错误：

- HPA 的分区内距离使用真实长度 Dijkstra，抽象边使用 double，跨分区对角边使用实际欧氏距离；启发式也改为欧氏距离。抽象边满足欧氏下界和三角一致性。最优终点候选仅在 arrival 更小时更新。
- 四邻 Eikonal 二次更新仍保留。八邻传播额外取合法实际边的 Bellman 候选与 Eikonal 候选的较小值；不是把流场替换成另一个隐藏的全局协调算法。
- 对角连通、分量、抽象门户、局部回退均调用实际半径的 CanEdge，后者包含完整圆盘 CanSegment。它允许真实圆之间的合法对角，同时拒绝闭格角点和基地弦穿透，不按“正交格被占据就禁止所有对角”误删合法连接。
- 局部运动后仍保留原静态 / 基地检查、所有实际身体的连续相对扫掠与只停不推位的碰撞收敛过程。临时规划圆不会使真实身体消失。
- GridGeometry.Reachable 的整数值仍是图跳数，用于候选自己的目标选择或策略阈值；HPA 的物理长度代价来自独立的加权 TileDistances，不混用跳数作物理启发式。

`query.json` 有七项实际固定 DLL 的只读查询：闭格角点拒绝、基地弦拒绝、正交位置被圆占据但真实对角净空 207.106mm 的连接允许、r700 对角余量与穿透区分、3458 条抽象边的实际长度与启发式一致性（2004 条含非整格代价）、HPA / 分段流 / FMM / 对角松弛实际执行，以及四邻 Eikonal 期望值 707.10678。

这些检查没有证明任意场景最优或全面普适。此前 R9 状态恢复中 actor20 的子格陷阱仍有单独保留，不能用 R10 原出生流程的开发 PASS 覆盖那个已知恢复边界。
