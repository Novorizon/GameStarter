# 真实波次：全部合法攻击格的兼容匹配

本记录只增加分析和独立构造，不修改生产程序、地图、holding、身体、速度或实际表配置。输入来自真实 `tdenemy.xlsx`、`tdwave.xlsx`、`tdspawn.xlsx` 和当前 ForestNavigation，指纹见 `manifest.json`。

攻击格按身体静态净空、身体边缘到基地边缘的真实攻击距离以及静态视线生成，不使用 frontier 过滤。Python 用圆盘距离和闭矩形射线独立生成集合；C# 逐格核对与实际 `NavigationGrid.HasAttackLine` 完全一致。

## 匹配之外的实际可行构造

单独的几何匹配不能证明进场可行。本程序先用最小费用最大流为**全部单位**分配互不重叠的合法最终位置，目标是在全部可站住的前提下使攻击人数最大；再按各单位自己的身体做逆向撤离，反转得到实际入场路径。

各单位保留真实速度及表内最早生成 tick。发车采用移动全程独占源/目标格的时序预约；不会提前生成、提高速度或丢弃单位。最后逐 tick 计算真实相对运动的最短圆盘间距，逐完整移动边独立检查基地圆和阻塞格，并在全部抵达后继续保持 200 tick。

这里允许外部生成队列延迟及不同发车顺序；构造没有优化总时长。表中的 tick 是可行性见证，不与生产调度比较性能，也不意味着生产使用了这些路径。它证明给出的最大攻击数可动态达到，而非仅在终态画几个圆。

每组完整分配、发车时间、逐格路径及检查计数见同目录对应 JSON。`summary.json` 保存七组结果，`input.json` 保存表输入及独立几何/最大流分配；旧的 44 Big + 2 Small 证据保持原样。

## 复现

在该分支根目录使用 Python（需 `openpyxl`）和 .NET 8：

```bash
python3 Verification~/NavigationFeasibility/BuildWaveAttackInput.py
dotnet run --project Verification~/NavigationFeasibility/WaveAttackFeasibility.csproj -c Release
```

用 `--root /path/to/GameStarter` 可读取其他 checkout 的实际表和地图；先重新生成输入，再运行 C#。C# 会拒绝地图/表指纹不匹配的旧输入，失败时清除对应输出及汇总，避免残留上一轮成功记录。

这是当前离散逻辑格、每格一个最终身体的攻击人数上界，不是任意连续位置或其他分辨率下的极限。真实伤害、Unity 状态与表现仍由主任务的原生验收覆盖。
