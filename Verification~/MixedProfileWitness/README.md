# 混合攻击范围的独立可行见证

此项目保存 B2 导航中两类真实失败的可行交换路径。它不运行生产规划器，而是从原失败日志中已经出现的静止阵型出发，构造逐格移动，并真实执行独立的连续几何检查。八组见证证明这些失败具有合法恢复方案；不能据此宣称生产算法已经修复。

## 复现

需要 .NET 8 SDK，无第三方 NuGet 包。仓库根目录执行：

```sh
dotnet run --project Verification~/MixedProfileWitness -- --output Artifacts/MixedProfileWitness
```

也可以单独复制整个 `MixedProfileWitness` 目录，在新目录执行：

```sh
dotnet run --project MixedProfileWitness.csproj -- --output Results
```

项目自带输入和冻结的独立 oracle，不依赖 Unity、生产 Domain、相邻验证项目或某个云端绝对目录。`--input` 可以指定输入目录，但每个文件仍须通过 `InputManifest.json` 中冻结的 SHA256 校验。`--output` 仅改变结果目录。

`Evidence/` 是本次归档运行产生的八份完整见证和汇总。每份见证包含全部活体的起终姿态、每次移动的完整格子路径、数量与攻击份额、逐步检查计数和输入 SHA。再次运行会重新执行碰撞检查，不是读取归档结果后返回成功。耗时、DLL SHA 可能随构建环境变化，物理路径和验收门槛保持不变。

## 原问题与门槛

固定 35×35 格、格长 1000mm、基地半径 1000mm、单位半径 250mm、速度每 tick 最多 1000mm、集结距离 10000mm。Long 射程 4000mm，Short 射程 1000mm。Long 有 84 个合法攻击格，Short 有 16 个且为 Long 的子集，因此最多 84 个单位同时攻击。

| 原失败类别 | 入口 seed | 保留活体 | 最终 Long 攻击/候场 | 最终 Short 攻击/候场 | 实际格移动数 | 包含 200 tick 保持后的完成 tick | 原截止 tick |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Long 先到 | 1 | 85 | 83 / 1 | 1 / 0 | 63 | 443 | 5000 |
| Long 先到 | 17 | 85 | 83 / 1 | 1 / 0 | 63 | 443 | 5000 |
| Long 先到 | 733 | 85 | 83 / 1 | 1 / 0 | 63 | 443 | 5000 |
| Long 先到 | 20261110 | 85 | 83 / 1 | 1 / 0 | 63 | 443 | 5000 |
| Short 先到，死亡补员被占位 | 1 | 100 | 68 / 16 | 16 / 0 | 63 | 483 | 2202 |
| Short 先到，死亡补员被占位 | 17 | 100 | 68 / 16 | 16 / 0 | 72 | 492 | 2203 |
| Short 先到，死亡补员被占位 | 733 | 100 | 68 / 16 | 16 / 0 | 74 | 494 | 2202 |
| Short 先到，死亡补员被占位 | 20261110 | 100 | 68 / 16 | 16 / 0 | 62 | 482 | 2201 |

这些 seed 对应左、下、右、上四个入口，不将其称为八种随机流量。见证不要求不可能的 85/100 人全部攻击，也不以总攻击数 84 掩盖 Short 永久无法攻击。

## 实际检查

每 tick 最多移动一个真实单位一个四邻格，其他单位原地保留。四个 Long 从入口方向临时退到不同合法候场格；Short 进入兼容的内层攻击格；外侧三个 Long 依次返回原位置，最内侧 Long 留在合法候场格。没有删除、替换、缩小或瞬移任何输入活体。

- 活体 ID 集合和原半径全程不变，逐 tick 位移不超过原速度。
- 使用冻结 oracle 检查连续圆盘碰撞、障碍矩形与基地圆盘的线段扫掠；另外独立枚举所有身体对，检查相对运动线段的最小距离。
- 验证攻击范围、攻击视线、候场范围、原目标集合和原截止时间；完成后继续保持 200 tick。
- 运行 oracle 的解析自检案例，并记录输入与源码的运行前后 SHA。

本次八例最小身体净隙均为 500mm，基地净隙均为约 164.214mm。这里只证明这八个已观察状态存在可行交换，不证明任意地图、体型或持续新请求下的完备性，也不替代真实 Unity 验收。

## 输入来源与可追溯性

原候选为 `experiment/navigation-all-legal-slots` 的 B2 提交 `445a7db`，Domain 逐文件摘要的聚合 SHA256 为 `a9ee55d0667eaea51207568e41c52c11aed2f78d1998af0031d78db656a24ef7`。原 76 组运行于 2026-11-10 完成，68 通过、这八组失败，原运行记录源码未发生变化。

原八份完整时间轨迹合计约 66MB。此处 `Inputs/` 保留原几何、命令和两个未改动的原始帧：首次与最终失败姿态完全相同的静止帧，以及最终失败帧；仅省略重复采样帧。所有已记录命令都早于所选静止帧，因此见证没有提前执行尚未发生的输入。这里不重放原始出生历史，原验收程序漏记失败出生调用的问题也不被此见证掩盖。

- `InputManifest.json`：原整日志、抽取帧和本地 fixture 的各自 SHA256。
- `SourceProvenance.json`：B2 源文件、原 76 组运行汇总与验证源码摘要，以及冻结 oracle 的来源和摘要。
- `Evidence/summary.json`：本次复现的程序、oracle、执行 DLL 与八个输入身份。
- `PortabilityVerification.json`：脱离仓库独立构建后的八组物理证据对照，以及被篡改输入的拒绝结果。
- `ArchiveManifest.json`：归档文件摘要，排除该清单自身和构建输出。

若持有原失败日志，可重新提取并逐字节核对冻结输入：

```sh
python3 Verification~/MixedProfileWitness/ExtractInputs.py /path/to/original-reports --output /tmp/reextracted-mixed-inputs
```

提取脚本同时验证原整日志和生成 fixture 的 SHA；源日志或提取结果不匹配时会失败。
