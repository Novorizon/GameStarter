# C：Supreme Commander 2 公开架构复现

来源是 Elijah Emerson 的开发者文章：[Game AI Pro 第23章](https://www.gameaipro.com/GameAIPro/GameAIPro_Chapter23_Crowd_Pathfinding_and_Steering_Using_Flow_Field_Tiles.pdf)。本文实际逐页阅读该10页原文；不是依据游戏名称猜测算法，也不是原版游戏源码。

原文明确披露了分区门户图、全局 A*、代价/积分/方向三个场、LOS 引导、门户流缓存、按移动类型与体型扩张障碍、动态脏区重建，以及单位推挤/沿墙滑动。这里按这些职责重新编写 C#，不调用 A 分支的 SIPP，也不使用 ORCA。

实现保留输入地图尺寸和单位参数；每分区为10×10输入格，字段使用浮点积分和四邻 Eikonal 更新，方向查询可以使用八邻与直视目标。分区尺寸、LOS 的逐段检查、确定性门户排序和具体缓存容量是本实验的工程选择。地形更新使受影响分区及相邻门户失效。

文章没有公开围攻目标分配、公平性或物理求解器代码。本实验另外实现合法攻击/候场位置分配、最大攻击/最小位移匹配、保守连续碰撞、局部避让与有限距离让位；这些属于本项目补充。推挤不能传送、缩小身体或让单位穿越障碍，产生的临停也不计为到位。

共同 Core/Runner 的输入、连续几何检查与身份守恒才是验收依据。通过范围、失败原例、源/测试指纹与实测结果在本分支 Evidence 中记录；有限场景通过不证明任意地图的完备性，也不代表商业二进制或手机已经验收。


当前复现边界：输入是2D地面、圆盘身体与离散候场位置。移动类别只按身体净空区分，没有实现飞行/悬浮、水陆转换或坡度代价输入。门户 A* 使用门户中心的同区最短路边与可复用后缀；积分采用优先波前 Eikonal 更新，边界波前用零代价，未采用论文可选的跨区代价携带。LOS 采用真实线段检查，未逐字复刻文章的阴影传播步骤。

局部推挤是可观察的请求/真实移动/返回协议，不使用传送或任意修改身体；攻击目标层的二分图匹配、停滞检测和公平性都是本项目补充。只有进入实际候场区、确有邻居阻挡且缺少进展时才重分配目标，外围蛇形路径不因欧氏距离增加而被误判成卡住。匹配最多处理160个近场单位，超过该规模仍使用原流场与局部避让；这是明确的工作预算，不是完整性保证。

全体单位都真实到达合法最终候场位置、没有临时让位或未完成目标迁移，并完成空攻击位与不同射程攻击服务检查之后，允许整组控制器休眠以消除静止后的分离抖动。它不是逐个单位提前停住；新出生尝试（包括拒绝）、死亡和地图/目标变更都会显式唤醒，再次补位后才可休眠。休眠不暂停外部出生、死亡或地图事件，也不将移动中单位记成到位。

临停不能占住请求者的永久目标并等待请求者先通过。局部让路无合法候选时，可以从同目标、同完整身体/速度/射程配置且已到位的单位中，找出能够沿真实安全直线迁入空目标的占有者，再原子交换两人的永久目标。两人都必须允许自由选目标；交换保持目标集合与该配置的最终攻击位置份额。只有实际迁入空位者的目标短暂受到保护，直到它真实到位；请求者仍允许原匹配调整。所有身体继续经过原每5ms连续相对扫掠，不预约未来走廊。

参与该恢复的单位在当前完整引导段对静态地形、全部当前身体都安全，且本微步相对扫掠也安全时，优先沿引导直走，避免分离评分把它偏离已验证的狭窄通道。普通导航保留原转向评分。该恢复、目标保护与物理资格是本实验补充，原文没有公开这套围攻协议，也没有因此获得全局收敛保证。

永久目标除了不能占同一个格，还必须按双方完整半径相容；不同格也可能重叠。出生分配与目标批量提交都检查这一点，匈牙利匹配产生相撞目标时不提交。该护栏不等于求出了任意密集端点集合的最优装箱。临停优先当前完整直线实际安全的出口；全部直接方案与兼容永久交换都没有解时，才允许空端点、静态连通的间接临停，沿原流场执行并触发已有的接力让路。它不承诺未来走廊空闲，每5ms仍受原完整扫掠约束。接触数值容差沿用既有安全运动的1e-6毫米，公共几何验收仍为0.1毫米。

对长期停滞、空间相邻、同完整配置和同目标的移动单位，补充一个只重排其现有目标集合的匹配。它保留原交通代价，在静态视线本来清晰时计入当前下一正常微步被身体挡住的代价，并用连续距离作弱二级项；不调换已到位者，也不跨配置强行交换。当前可走一步不代表未来路线可完成，因此这一层仍可能反复换位，计数表示接受的目标重排次数，不表示成功验收次数。它不能替代跨体型的接力让位或完整联合规划。

`Evidence/Exploration` 保留失败迭代。v10 是交通感知目标匹配；v11 的逐人提前冻结、v12—v15 的接触投影探索均未采用，不能拿它们的算法名称或中断进度宣称通过。最终实现回到连续安全运动，并增加上述全体完成后的稳定状态。正式最终结果以绑定源和 DLL 指纹的独立 Runner 报告为准。
