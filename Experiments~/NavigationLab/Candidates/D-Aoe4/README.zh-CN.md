# D：依据《帝国时代 IV》公开架构实现的导航候选

本候选是独立 C# 实验，基线为 GameStarter `8c0dd50`。它不包含或声称恢复微软/Relic 的商业源码。

## 核实到的一手来源

- Frank Cheng（World's Edge），GDC 2022：[演讲页面](https://gdcvault.com/play/1028036/Pathing-in-Age-of-Empires)。
- [GDC 官方完整幻灯片](https://media.gdcvault.com/GDC+2022/Speaker+Slides/Pathing+In+Age_Cheng_Frank+2022-03-29+00.16.38.pdf)，本轮已实际下载并阅读，共36个PDF页。PDF页码与幻灯片编号一致到35，最后另有致谢/活动信息。

公开资料确证：地形按块抽象出连接入口，块间搜索决定流场覆盖；方向由代价积分生成，LOS区域与FMM结合；为避免单块边界质量下降，可用重叠分段计算和缓存；混合通行限制从较受限类型扩展；局部控制同时考虑移动单位、不动单位和静态小障碍。幻灯片还介绍了编队与水陆接驳，后两者不在本轮统一地面塔防模型中。

## 本候选的具体选择

下面的参数与业务策略由本项目实现，不声称是商业游戏内部值：

- 8×8逻辑格为一个块；每个边界可通行格为入口节点，块内连接代价用四邻格最短路计算。
- 先在入口图做A*，随后在三块重叠片段中计算LOS/FMM距离及方向，按需推进；缓存按世界修订、身体半径、出口和片段覆盖区分。
- 混合体型允许以最大注册半径的合法距离值作为种子，再扩展到较小半径可走的区域。目标/片段对大体型不可达时独立计算，不捏造共享。
- 局部控制采用候选方向采样与邻居预测，连续圆盘运动由明确的物理停止规则约束；停止/冲突提案单独计数，不能靠碰撞夹紧被动宣称已到达。
- 最终驻留格、射程、排队、死亡补位和可选的显式让路属于塔防适配，不是GDC披露的攻击调度算法。基础与增强版本分别报告。

实现不调用 A 的 SIPP 或 B 的 ORCA。具体参数、功能覆盖及失败反例由统一 NavigationLab Runner 的冻结报告说明；有限测试不构成一般完备性保证。
